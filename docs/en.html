02 / THE BUILDING BLOCKS

Components become
a structure.

Four directly modelled node types from the EngineeringToolbox AutomationBase library.

applicationUnit

Application Unit

Machine, motion, workpiece or process unit. A unit connects the ET state model to commands and project-specific data contracts.

Generates: command enum, request/status DUTs, base FB

commandUnit

Command Unit

Command execution and sequence coordination without a separate ET state model. You write the actual CASE or sequence logic in the project.

Generates: command and contract scaffold

recipeManager

Recipe Manager

Describe the recipe data type, file, path and options. Domain data structures and validation logic remain project-specific.

Generates: instance, configuration, status contract

machineLink

Machine Link

Model a logical machine connection with role, bridge type, watchdog and token options. Hardware addressing is configured in the project.

Generates: instance, Rx/Tx and status contract

Output depends on the model, node type and enabled options.

Conflicts block writes

Invalid or unsaved models, conflicts and stale previews prevent generation. Duplicate IEC object names are checked in advance.

Managed artifacts stay traceable

ETAB manages the files and entries recorded in its manifest. Optional ApplicationUnit user stubs are created once and are not overwritten afterwards.

Cyclic execution is optional

When runtime generation is enabled, the preview also shows the planned task change. Ambiguous task assignments are blocked.

Your process logic stays with you

The model describes structure and contracts. Process sequences, hardware binding and machine behaviour still need their own implementation and verification.

Current evidence for v0.1.0.8

For the OmniGrind model, the README documents 36 nodes, 62 relationships and 168 managed artifacts, along with a successful TwinCAT "Rebuild All". Online runtime, simulation, safety and machine acceptance are separate checks that remain necessary. Status and evidence ↗

04 / INSTALLATION

On your
engineering PC.

The Windows x64 version includes the application and local service. The target computer needs neither the .NET SDK nor Node.js.

Install ETAB

Run the installer. A normal installation is per-user without elevation. If WebView2 is missing, Setup installs the runtime through Microsoft.

Prepare the libraries

Use ET_AutomationBase 0.1.0.4 and the original EngineeringToolbox dependency. The library is provided separately.

Select a PLC project

Create an empty PLC project in TwinCAT. Open ETAB and choose "Connect TwinCAT PLC Project". Then model your first machine structure.

06 / GOOD TO KNOW

Before your first project.

Does ETAB Engineering run in a browser?

The released application is a Windows desktop program with WebView2 and a local service. This website explains the tool and links to downloads. It does not access your PLC project.

Does ETAB generate a complete machine controller?

ETAB generates a structured PLC template from your model. Domain sequences, project-specific logic, hardware addressing and machine acceptance remain engineering tasks.

What happens to existing code?

Project integration distinguishes managed artifacts from existing project files. Compatible existing entries are not taken over, and conflicts block writes. Still review the concrete preview before each generation and keep your projects under version control.

What are the TwinCAT prerequisites?

You need a TwinCAT PLC project and the EngineeringToolbox and ET_AutomationBase libraries. This does not claim approval for every TwinCAT version or machine configuration. See the repository validation records for the tested scope.
